# Phase 2B — Data and Content Correctness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt Sanity's generated `sanity.types.ts` as the source of truth for the six route files'
payload types (fixing the three real bugs the divergence exposes), harden `/api/revalidate` with
unit tests, fix the image pipeline's hotspot-fraction-as-pixel-dimension bug at its two call sites,
and add the missing `internalLink` portable-text renderer.

**Architecture:** No new subsystems. This phase tightens existing seams: `types/index.ts` changes
from a hand-written, independently-drifted set of interfaces into a thin layer derived from
`sanity.types.ts`'s TypeGen output; `app/api/revalidate/route.ts` gets an explicit validation guard
plus its first unit tests; `ImageBox`/`ImageContainer` stop being handed hotspot fraction data as if
it were pixel dimensions; `CustomPortableText.tsx` gains one more mark renderer.

**Tech Stack:** Next.js 16 (App Router), Sanity 6 + `next-sanity` 13, TypeScript 5 (`strict: true`),
Vitest 4 (from Phase 2A — `vitest.config.ts` includes `**/*.test.ts`, node environment, no DOM), GROQ.

**Baseline verified:** `main` @ `8ef9253` (Phase 2A merged, PR #5), 2026-08-10. Every file:line citation
below was re-read against this commit during this plan's research — not copied from the foundations
doc without checking. `git diff --stat 683aba5 HEAD -- app/ components/ lib/ types/ schemas/
sanity.types.ts` confirms Phase 2A touched none of the files this plan modifies (it only added test
infrastructure), so the foundations doc's research (also against this lineage) is current.

## Context for the implementer

`types/index.ts` today is a hand-written set of interfaces that predates Sanity TypeGen and has
drifted from what the actual GROQ queries return. `sanity.types.ts` is TypeGen output, generated by
`npm run typegen` from the query strings in `lib/sanity.queries.ts`, and is checked into git —  but
nothing in `app/`, `components/`, or `lib/` imports it today. The six route files that fetch data
(`app/page.tsx`, `app/[slug]/page.tsx`, `app/people/page.tsx`, `app/contact/page.tsx`,
`app/publications/page.tsx`, `app/projects/[slug]/page.tsx`) each cast `sanityFetch`'s `data` — which
is typed `unknown` because the `groq` template tag's return type is widened to plain `string`,
so `sanityFetch`'s `<const QueryString extends string>` generic can never narrow to a specific
`SanityQueries` key — to `types/index.ts`'s hand-written interfaces via `as X`. Because the cast
source is `unknown`, TypeScript can't catch that the cast target disagrees with what TypeGen (working
from the real query and schema) says the shape actually is.

Task 1 below keeps the `as X` casts (retargeting them would require moving off the `groq` tag, which
is out of scope — see Global Constraints) but changes what `X` **means**: `types/index.ts`'s
exported names stay the same, but their definitions become derived from `sanity.types.ts`'s generated
`*QueryResult` types instead of hand-written from scratch. This is why the plan doesn't touch the
16 cast expressions themselves — only what `types/index.ts` says those names mean, and the
consuming-component code that has to adjust to fields becoming honestly nullable.

- [ ] **Step 14: Harden `app/[slug]/page.tsx`'s `generateStaticParams` against null slugs**

  `pagePaths`'s generated result type (`PagePathsResult` in `sanity.types.ts`) is
  `Array<string | null>` even though the GROQ query filters `slug.current != null` — TypeGen doesn't
  narrow away nulls from filter conditions, so the existing `client.fetch<string[]>(pagePaths)` cast
  is itself an unchecked assertion. Fix it to reflect reality and filter defensively, which is the
  concrete form of the "add an explicit guard wherever a null slug would otherwise flow into
  `generateStaticParams`" fix called for by this phase's design doc.

  In `app/[slug]/page.tsx`, add to the existing type-only import block:

  ```ts
  import type { PagePathsResult } from 'sanity.types'
  ```

  Then change:

  ```ts
  export async function generateStaticParams() {
    const client = getClient()
    const slugs = await client.fetch<string[]>(pagePaths)
    return slugs.map((slug) => ({ slug }))
  }
  ```

  to:

  ```ts
  export async function generateStaticParams() {
    const client = getClient()
    const slugs = await client.fetch<PagePathsResult>(pagePaths)
    return slugs
      .filter((slug): slug is string => Boolean(slug))
      .map((slug) => ({ slug }))
  ```
